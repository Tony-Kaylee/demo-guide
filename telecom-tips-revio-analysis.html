📋 Executive Summary

This document analyzes your existing TIPS (Telecom Inventory and Provisioning System) workflow — including Circuit Entry, Service Order Creation, and Service Provider Order Management — and maps each capability to Rev.io PSA. Rev.io PSA is a purpose-built telecom BSS/PSA platform with native support for provisioning workflows, circuit inventory, purchase order management, and recurring billing. The majority of your core provisioning process can be replicated within Rev.io PSA, with a few gaps primarily in external accounting system integration.

Bottom line: Rev.io PSA can serve as a direct replacement for TIPS's circuit inventory, purchase order, and service provider order tracking functions. The primary gaps are integration with Great Plains (GP) accounting and TEOCO Bill Track on Demand — both handled through Rev.io's QuickBooks Online integration or via API. Salesforce and TaskRay functions are addressed through Rev.io's native project management, workflow automation, and the Rev.io–Salesforce integration.

🔌 Process 1: Circuit Inventory Entry (TIPS Circuit Form)

The TIPS Circuit Entry process captures all technical, billing, and configuration details for each active or disconnected telecom circuit. Here is how Rev.io PSA handles each step.

✅ Rev.io PSA Can Do

  • Create and maintain circuit inventory records as Asset records with full lifecycle tracking
  • Store Circuit Name, Type, and Status (Active / Disconnected)
  • Track Service Provider using native Provider management module
  • Store Service ID as the Serial Number — serialized asset tracking with full movement history
  • Record Upload/Download Bandwidth, MRC, NRC via custom fields
  • Manage Term Agreement and Term End Date via the Agreements module
  • Store LAN/WAN/IP configuration via Asset record's built-in device fields (IP Address, MAC, OS, custom fields for Gateway, Subnet, DNS)
  • Link circuit to customer site/facility via Customer Service Address
  • Attach documents (vendor docs, config sheets, install confirmations) at the asset level
  • Notes and activity feed for ongoing updates and audit trail
  • Mark circuit as Active or Disconnected with status badges
  • Full inventory history — 1,100+ transaction audit log
  • Shared Circuit tracking via custom field

⚙️ Requires Configuration / ❌ Gaps

  • Bandwidth Mbps, Handoff Type, Connector, ISP DEMARC fields — need to be added as custom fields on the Asset module (easy config, no development needed)
  • Billing Start PO / Billing Vendor # — custom fields required
  • Circuit Type dropdown values (DIA-Ethernet, Satellite, Broadband, Fixed Wireless) — must be configured as Asset Types or custom dropdown values
  • TEOCO Bill Track on Demand integration — ❌ not available. Invoice audit workflow can partially replace this manually.
  • Auto-population of DMARC from PO — requires workflow automation configuration (not out-of-the-box)
Rev.io PSA Tip: The Asset module's "Convert to Asset" toggle means any product installed during a ticket can automatically generate a circuit asset record, linking the installation ticket to the circuit inventory entry without manual re-entry.
📄 Process 2: Service Order (PO) Creation

The TIPS Service Order process covers creating Purchase Orders for ISP provisioning requests — new installations, changes, and disconnects. Rev.io PSA has a native PO module purpose-built for this workflow.

✅ Rev.io PSA Can Do

  • Native Purchase Order module — create, track, and manage POs for any vendor/ISP
  • Auto-generated PO number on save (same "enter period to auto-assign" behavior)
  • Link PO to Provider (ISP/vendor record), Customer/Site, and Project
  • Status tracking: In Progress, On Hold, Completed, Closed
  • Requestor and Provisioner assignment on the PO record
  • Requested Due Date and Estimated Due Date fields
  • Telecom Service Type via custom field or product selection
  • Notes / chatter equivalent — time-stamped activity feed per PO
  • Document attachments (SOW, confirmations, emails) directly on PO
  • Link PO to service tickets and project for full traceability
  • Bulk export and reporting via Analytics dashboards

⚙️ Requires Configuration / ❌ Gaps

  • Order Type (New / Change / Disconnect) — custom field on PO (dropdown, easy config)
  • Project Ticket / Project ID reference — custom field linking to project (PO ↔ Project linkage needs config)
  • Project Scope field — custom text field on PO
  • Status Reason values (In-Jeopardy, In-Progress, Hold-Construction) — configurable ticket/PO status values
  • DMARC Address on PO — custom address fields required (DMARC Unique ID, Address, City, State, Zip)
  • TaskRay Chatter log from PO — Rev.io Notes feed replaces this; no direct TaskRay integration
Process mapping: TIPS PO → Rev.io Purchase Order. The full PO lifecycle (create → in progress → pending TTU → closed) maps directly to Rev.io PO statuses. Vendors/ISPs are managed in Rev.io's Provider module (ADI, Lumen, Comcast, etc. already supported as Provider types).
🌐 Process 3: Service Provider Order (SPO) Tracking

The TIPS SPO process manages order tracking with ISPs from initial submission through FOC, installation, and close-out. Rev.io PSA handles this through its Service Ticket and Project workflow.

✅ Rev.io PSA Can Do

  • Service Provider Order maps to a Service Ticket (type: Sales Order or custom "ISP Provisioning Order" type)
  • Auto-generated SPO number (ticket ID)
  • Order Issued Date and Estimated Due Date — native ticket date fields
  • Circuit Type and Service Provider — linked PO and provider record
  • Status tracking through the full order lifecycle (New → In Progress → Complete)
  • Notes/activity feed for real-time ISP update logging with timestamps and user attribution
  • Document attachments: quotes, ISP order confirmations, emails, SOWs, design docs, signed contracts
  • Facility Site auto-linked from parent customer/PO
  • FOC date captured as custom field or milestone
  • Service Ready Date field (custom date field)
  • Milestone and task tracking via Projects module
  • Project task creation and assignment on linked project
  • Workflow automation triggers on status changes (e.g., notify provisioner when FOC received)
  • Full audit trail — 3,600+ entry audit log

⚙️ Requires Configuration / ❌ Gaps

  • FOC date as dedicated field — custom date field on ticket (not out-of-box but simple config)
  • "Onsite Install Activity" field equivalent — custom field or milestone date on project
  • Direct ISP portal / ordering system integration — ❌ order submission still via ISP portal or email; Rev.io tracks the record, not the submission channel
  • Service Ready Date — custom date field on ticket or asset
  • PO Closed / Pending TTU status — configurable as PO status values

Key Gap: Your current process sends check requests and JEs to Great Plains (Dynamics GP). Rev.io PSA integrates with QuickBooks Online only — not GP. If your organization is committed to Great Plains for accounting, a custom API integration would be required, or Rev.io's data export (CSV/Excel) could be used to manually post to GP. This is the most significant gap to address in any implementation plan.
🚀 Recommendations & Implementation Path
1Configuration Required (No Development Needed)

The following items require custom field setup in Rev.io PSA Admin → Custom Fields Manager. These are straightforward configurations an admin can complete during implementation:

  • Order Type (New / Change / Disconnect) — dropdown on PO and Ticket
  • DMARC Address (Unique ID, Address, City, State, Zip) — text/address fields on PO and Asset
  • FOC Date (Firm Order Commitment) — date field on Ticket
  • Service Ready Date — date field on Ticket or Asset
  • Billing Start Date, Billing Start PO, Billing Vendor # — date/text fields on Asset
  • Circuit bandwidth (Upload/Download Mbps) — numeric fields on Asset
  • Handoff Type (Copper/SMF/MMF), Connector (RJ45/SC/LC), ISP DEMARC — dropdown/text fields on Asset
  • Circuit Use — dropdown field on Asset
  • Circuit Type values (DIA-Ethernet, Satellite, Broadband, Fixed Wireless) — configurable Asset Type values
2Workflow Automation (Low Effort, High Value)
  • Auto-trigger circuit asset creation when SPO ticket is marked Complete
  • Auto-notify provisioner when PO status changes to "Pending TTU"
  • SLA policy on provisioning tickets to flag overdue FOC dates
  • Workflow to auto-populate DMARC address from PO onto linked SPO ticket
